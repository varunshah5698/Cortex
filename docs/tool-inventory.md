# Tool inventory

One row per capability the harness or its agents can actually use. A tool whose
justification cannot be written down should be removed; a blank control column is an
incident waiting to happen. The enforced policy lives in `src/ai_harness/modules/permissions.py`
and is reported by `GET /api/health`.

| Tool or action | Why the agent needs it | Worst case, and the control |
| --- | --- | --- |
| `tools/file_manager.py` — scaffold and write a file in the run | Shipping the artifact is the point of the run | Overwriting outside the run's sandbox. Control: every path resolves through `utils/validators.safe_relative`; refusals are `error` events; byte and line quotas in `config/settings.py` |
| `tools/web_search.py` — search, then fetch one page | Grounding the build in something real when the request names it | Fetching an internal address (SSRF) or looping on the network. Control: `utils/netguard.py` refuses link-local/metadata hosts; at most 3 queries and 2 pages per run |
| `tools/terminal.py` — read-only inspection | Let a specialist look at the tree instead of guessing at it | Shell injection, credential reads. Control: off unless `HARNESS_ALLOW_TERMINAL=1`; program allowlist (`ls`, `cat`, `grep`, …); metacharacters refused; `permissions.decision` deny rules (`cat .env` is denied by path); cwd is the run workspace |
| `modules/agent_loop.py` — `read`, `list`, `search` | A revision should inspect the actual file and its peers, not a 7,000-character guess | Reading outside the sandbox, or reading a key store. Control: every path resolves through `FileManager`/`safe_relative`; `list`/`search` skip dotfiles; results are clipped; the working set is capped by `HARNESS_AGENT_ACTIVE_FILES` and `HARNESS_AGENT_CONTEXT_CHARS` |
| `modules/code_search.py` — `grep` | A literal match cannot answer "where is this defined"; a regex can, and it is one call instead of a guess | A catastrophic-backtracking pattern stalling the loop, or a broad pattern drowning the model in matches. Control: patterns compile before use and an invalid one is an observation, not a crash; the match runs in a child process killed at a 2 s budget, so a backtracking pattern cannot stall the loop; 60-match cap with an explicit "narrow this" note; 256 KB per-file cap; dotfiles and harness bookkeeping excluded; every read still goes through the loop's `FileManager` |
| `modules/shell.py` — `shell` | Some questions (does it build, what does the tree look like on disk) are cheaper to answer with one command than with ten reads | Arbitrary command execution with the owner's access — the workshop's `bash -c` shape. Control: off unless `HARNESS_AGENT_SHELL=1` **and** `sandbox.available()`; one argv, no shell in between, metacharacters (`|`, `;`, `>`, `$(`, backtick, newline) refused so one judged command cannot become several; `permissions.decision` must return `allow` — an `ask` is refused because a repair loop has nobody to approve it; `sandbox.prefix` contains the child; `permissions.safe_env` strips keys and `HARNESS_*`; 20s timeout; output clipped to 4000 chars |
| `modules/agent_loop.py` — `edit`, `write` | A targeted fix is how one broken selector stops costing a whole file | Overwriting outside the run, weakening a test, or bloating the tree. Control: the same `FileManager`, `safe_relative`, `protected.frozen` and byte limit as any other write; `edit` refuses an absent or non-unique `find`; the tool loop is bounded by `HARNESS_AGENT_STEPS` |
| `modules/agent_loop.py` — `delegate` | A question that needs several files read pollutes the parent's prompt with all of them; a subagent answers it in its own context and returns one line | A delegate that edits the tree, or one that never stops. Control: `modules/subagent.py` offers only `list`, `read`, `search`, `answer` — no `write` or `edit`; a request for one is refused **and recorded** as a failed tool event; `HARNESS_SUBAGENT_STEPS` bounds it; every read still resolves through the loop's `FileManager`; a provider error returns `complete=False` instead of raising |
| `modules/hooks.py` — `PreToolUse` / `PostToolUse` | An operator needs to add a boundary or an annotation without editing a node, and a rule mounted at the tool-log choke point covers every current and future tool at once | A hook that executes code, or one that silently swallows a tool. Control: rules are **declarative only** (`match` + optional path glob → `deny`/`allow`/`note`) and cannot run a command, so a hook file is never a second execution path outside `modules/sandbox.py`; a deny raises and emits a `hook` event before it does, and the repair loop turns that refusal into the tool's observation instead of ending the revision; a post rule observes and cannot change a result; a malformed config is inert, not fatal; `HARNESS_HOOKS=0` disables the system |
| `modules/tasks.py` — the task graph | A checklist cannot express order, so a model that loses the thread starts blocked work and imports a file nobody wrote | A claim race handing one task to two owners, or a graph that lies after a restart. Control: `claim()` is a check-then-set under a module lock (a real one: threads, not just coroutines); `ready()` is the only sanctioned pick and refuses a task with an unfinished blocker; every mutation rewrites `.harness-tasks.json` through `FileManager`, so a resume reads the graph rather than re-deriving it |
| `modules/goal.py` — the goal gate | The verifier answers "does this tree hold together", not "is this what was asked for"; a run can pass every check and still stop early | A gate that blocks good runs, or one a model can talk into agreeing. Control: a mechanical sensor (`modules/intent.py` coverage) always wins and costs no call; it refuses only at the same bar `intent_unmet` uses — several capabilities named, none present — so partial coverage stays with the reviewer; an unreadable evaluator answer is `unknown`, **never** `met`; a failing evaluator is `unknown`, not a refusal; `HARNESS_GOAL_GATE=0` disables it |
| `modules/agent_loop.py` — `check` | The author must see the harness's facts before declaring the fix done | A model grading itself. Control: the tool calls `nodes/verify.py` (deterministic) and `done` is refused while the report has errors; a check is forced after any edit |
| `modules/runner.py` — `npm install` | The plan declares a `package.json`; without installs the build cannot run | Install scripts from the model's manifest execute on this machine. Control: **approval checkpoint** — the whole pipeline is planned first (`Service.plan()`) and an `ask` command blocks the start in `needs_approval` until a request carries `approve=1`; `permissions.safe_env()` strips provider keys and `HARNESS_*`; install timeout bounds it |
| `modules/runner.py` — `npm run build` | A React/Vite run is meaningless unless it compiles | The build script is arbitrary Node code. Control: same approval checkpoint (planned and listed before anything runs); deny rules for `curl`/`wget`/`git push`/`npm publish`; build timeout |
| `modules/runner.py` — `npm run dev` | Some stacks only exist under their dev server | Same as build, plus a long-lived process. Control: free loopback port only, `BROWSER=none`, `CI=1`, approval required, killed with its process group on stop |
| `modules/runner.py` — `pip install -r requirements.txt` | A Python run declares dependencies | Setup code from the model's requirements runs. Control: approval checkpoint; `pip install git+…` denied outright; install timeout |
| `modules/runner.py` — `uvicorn app:app` | Serving the Python app is how it gets verified | Executes model-authored Python as a server. Control: approval checkpoint; bound to `127.0.0.1` on a free port; the port is never advertised — the UI reaches it only through the preview proxy's per-run token |
| `modules/static_server.py` — serve a built tree | A static build needs a real origin for absolute `/assets/…` URLs | Serving a path outside the tree, or a local page reading it by scanning ports (a navigation carries no header to check). Control: `permissions.py` marks it `allow` (harness-owned, read-only); path containment in the server; loopback only; served only under the run's nonce (`--prefix`), every other path a 404 |
| `preview.py` — `GET /preview/{run}/{path}` on its own port | Looking at generated files without running them | Path traversal, or preview code reading `/api`. Control: separate origin with **no `/api` at all**, so a run's script can only reach the API cross-origin and the API refuses a foreign `Origin`; `safe_relative` containment; `permissions.DENY_PATHS` refused; `nosniff` + `no-store` |
| `preview.py` — `GET /live/{run}/{token}/…` proxy | The served app is arbitrary code and cannot be given auth, so it must not be reachable by port alone | Anyone on the machine hitting the model's server directly, or a leaked URL. Control: per-run secret (`Service.share`, `token_urlsafe(18)`, compared with `compare_digest`); the port is never sent to the browser; hop-by-hop headers stripped |
| `modules/browser.py` + `scripts/browser_check.mjs` — headless Chrome | A page can load and still throw, blank itself, or have a button that does nothing; only a browser sees that | Running model-authored JavaScript outside the preview. Control: only runs after the preview is ready (which required approval), loopback URL only, `permissions.safe_env` strips keys, Chrome profile is a temp dir, 30s timeout, `HARNESS_BROWSER_CHECK=0` disables it; it reports, it does not flip `done` |
| `share.py` + `modules/cloud.py` — one-run public tunnel | The person who asked for the page may not be on this machine | A tunnel in front of the multi-run preview app would expose every run, and `/api` would expose the harness. Control: a dedicated app has **one run id baked in** and a path token; no `/api`; the first request is `needs_approval`, `HARNESS_SHARE_TTL` bounds it, stopping the preview or the harness kills it, and the tunnel is a harness-owned process with `permissions.safe_env` |
| `cloud_runner.py` + `modules/cloud_runner.py` — per-run cloud execution | The generated app should run somewhere other than the harness host | Arbitrary generated code on a shared cloud instance. Control: a separate service with no `/api` and no provider keys; `POST /runs` needs `HARNESS_RUNNER_TOKEN`; archive extraction refuses links, devices and `..`; the public path has a per-run secret; one run at a time; `HARNESS_RUNNER_TTL` deletes it; the runner log states whether it has a sandbox |
| `modules/vercel_runner.py` — per-run Vercel deployment | Static/Node runs should execute on cloud hosting without a second server | Publishing generated code under the owner's Vercel account. Control: exact `cortex-<run_id>` project, SSO protection disabled only for that temporary project, removed at `HARNESS_VERCEL_TTL` or on stop, CLI login/token server-side only, no provider keys in the build; Python trees fall back to the local runner |
| `modules/toolchain.py` — the artifact's own `tsc --noEmit` | A type error is invisible to a structural check; only the compiler knows | Executing a model-installed compiler. Control: runs only when `node_modules/typescript` already exists (so an install was approved), `HARNESS_TYPECHECK=0` disables it, 120s timeout, stripped environment, `.py` files are compiled in-process and never imported |
| `modules/sandbox.py` — contain every child process | Approving `npm install` approves whatever an install script does | A dependency writing into the owner's home or reading a key. Control: macOS `sandbox-exec` profile — writes denied under `$HOME` except the run workspace and caches, `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.netrc`, `~/.config/gh` unreadable; harness says in the log when no sandbox is available instead of implying one |
| `modules/mcp.py` — one allow-listed, read-only MCP server | The team needs one real system, not ten imagined ones | A remote caller gaining write access or the build through a server. Control: stdio only; a tool is callable only when it advertises `readOnlyHint` (or a read verb) **and** is in the server's `allow` list; starting the server needs `"allow_exec": true` in `harness.mcp.json`; 20s timeout; output clipped to 4000 chars |
| `POST /api/run/{id}/preview-check` — drive the served app in Chrome | "It loads and the button does nothing" is the failure no file check can see | Opening an arbitrary URL in a browser. Control: only the runner's own service URL, one click, 30s timeout, killed process group, `permissions.safe_env`; without Chrome it falls back to `probe.py`, which fetches the page and assets limited to the page's own host |
| `POST /api/run/{id}/resume` — continue from disk | A run that dies after building should not pay for the build twice | Re-running a run under its old id with different inputs. Control: the plan and files come from the run's own workspace, the terminal event is dropped first, and a run with no `.harness-plan.json` refuses instead of re-planning |
| `modules/llm.py` — provider calls | The models are the workers | Unbounded spend, or hammering a provider. Control: budget checked before each request (tokens, dollars, calls); per-model prices; retry that never retries auth failures; cache only at temperature 0; an optional single fallback model (`HARNESS_FALLBACK_MODEL`) so a hard outage does not end the run |
| `modules/roster.py` — provider keys | A key must never live in the browser | Reading keys back out. Control: written once to a `0600` file; `/api/roster` reports `has_key`, never the value; `/api` refuses foreign origins and requires `x-harness-token` |
| `GET /api/run/{id}/events` — SSE stream | Watching the room is the product | Streaming a run to a foreign page. Control: origin check plus token; loopback only |
| `POST /api/run/{id}/serve` — the approval itself | Somebody has to decide, and the decision should be informed | Approving blind. Control: returns `needs_approval` with the full command list; only `approve=1` proceeds; `HARNESS_REQUIRE_APPROVAL=0` exists for unattended CI and is off by default |

## Policy

`modules/permissions.py` holds an ordered rule table — deny, then ask, then allow — and a
command that matches no rule is **denied**, so a new capability is a deliberate rule rather
than an assumption. `denied_path()` refuses credentials and the harness's own trust store
(`.env`, `.harness-token`, `.harness-roster.json`, `.harness-keys.json`, keys, `secrets/*`) even inside an
allowed command. The decision for a whole pipeline is made before the first spawn:
`Service.plan()` lists what would run, `Service.start()` stops at `needs_approval`, and
`_spawn()` re-checks every command as defence in depth.
